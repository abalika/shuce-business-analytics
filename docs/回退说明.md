# 备份、恢复与回退

源码版本与业务数据备份分别保管。公开仓库不包含任何工作数据库或业务备份。

## 数据维护

停止写入后，在项目根目录执行；只在返回 ok: true 时认为成功：

```powershell
.venv\Scripts\python.exe scripts/maintain.py check --data demo-data
.venv\Scripts\python.exe scripts/maintain.py backup --data demo-data --archive backups/before-change.zip
.venv\Scripts\python.exe scripts/maintain.py verify --archive backups/before-change.zip
.venv\Scripts\python.exe scripts/maintain.py restore --archive backups/before-change.zip --to work/restored-data
.venv\Scripts\python.exe scripts/maintain.py check --data work/restored-data
```

目标目录必须不存在。损坏或校验失败的备份不能恢复；保留原包，改用另一份已验证备份。恢复失败不会覆盖原库。用离线模式、另一端口与恢复副本核查历史报告，确认后才切换使用。普通业务库把 --data demo-data 改为 --data data。

## 源码回退

每个公开 Release 保留源码 ZIP、SHA256、版本号和更新记录。升级前停止数策并验证业务备份，下载目标 Release 后核对 SHA256，解压到全新目录，重新安装锁定依赖。用已恢复的数据副本离线核查，不直接用旧 ZIP 覆盖当前源码，也不直接把旧库覆盖现库。

初次公开版本没有此前的公开标签；2.4.0 本地旧包和原项目保留，但不作为已脱敏的公共附件。新版本以后通过 Release 标签继续保留回退入口。任意版本的数据无损降级没有保证，必须在副本上验证。

本地也可运行 scripts/checkpoint.py 英文编号 创建不覆盖已有文件的源码检查点；路径在 work/checkpoints/。检查点不含密钥、依赖与业务数据。Git commit 记录源码，不能替代业务备份。
