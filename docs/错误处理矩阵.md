# 错误处理与恢复矩阵

本轮新增 36 条 Python 故障/边界用例，文件 `tests/test_release_matrix.py`；此前用例继续回归。下表列出实际断言范围，验证结果见最终审查与 JUnit。

| 故障 | 对用户的处理 | 恢复路径 | 自动验证 |
| --- | --- | --- | --- |
| 空文件 | 422 可读解析/行数提示，不登记来源 | 填写模板数据重新上传 | 三表 empty |
| 缺必需列 | 422 列映射提示 | 补列或确认字段映射 | 三表 missing_column |
| 重复唯一键 | 保留原行，质量阻断与诊断 | 核查事件/目标/日期唯一键，重新导入 | 三表 duplicate + 旧重复阻断测试 |
| 编码乱码 | 422 编码提示 | 另存 UTF-8 CSV | 三表 encoding |
| 超大文件/行数 | 100MB 及各表行数边界拒绝 | 按期间拆分，保留必要核查记录 | 实际 100MB+1 输入 + 原行数边界 |
| 超长文本 | 422 长度提示，不回显完整输入 | 缩短到明确字段上限 | 报告 3 字段 + 任务 3 字段 |
| 服务断网/未启动 | 可读连接失败提示 | 保留草稿，启动服务，先核查历史 | JS api-feedback；离线两种配置主流程 |
| 模型超时/断网 | 有限重试，保留失败轨迹 | 稍后再试或使用结构化条件 | timeout / connect 注入 |
| 模型认证/余额/限流 | 401/402 不重试；429/503 最多两次 | 修复配置/额度或稍后重试 | provider 6 场景；结构化分析恢复 |
| 并发保存 | 相同内容复用；不同内容保留各版本 | 历史中核对正文与父报告 | 4 线程同文/异文保存 |
| 重复提交 | 同一父快照与正文返回同一报告 | 先查历史，重试不生成副本 | 同文并发及再次 HTTP 保存 |
| 备份损坏 | CLI 非零 + 可读提示，不创建恢复目标 | 保留坏包，换已校验备份恢复新目录 | 4 种坏包 + 原清单/内容损坏测试 |
| 数据库锁/磁盘权限/空间不足 | 503 可读提示 | 保留草稿、检查占用/磁盘、先查历史 | 原存储矩阵继续回归 |
| 未预期程序异常 | 503 + 事件编号，不裸露堆栈 | 保留草稿、先查历史，提供编号查日志 | 3 种异常注入，检查响应与日志脱敏 |

注入测试不等于真实提供方负载压测。并发保存验证只覆盖不可变报告保存，不代表支持公司多人共同编辑、权限或通用分布式幂等。异常的 503 状态表示未确认完成，不应盲目重复提交。
