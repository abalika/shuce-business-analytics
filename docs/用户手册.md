# 数策 v2.7 用户手册

数策用于把销售、目标、日运营三张表整理成可复核的门店/商品经营复盘。默认是个人电脑上的本地工作台。适合业务分析演示和小规模内部试用；上线给全公司使用仍需要权限、多人协作、数据治理与实际用户验证。

## 第一次使用

仅看成果：打开交付包中 `outputs/offline-demo-v2.7.0/index.html`，再打开报告。无需 Python、网络或 API。Excel、JSON、三张模拟源表与三种证据 CSV 在同一目录。静态报告不能交互计算，明确标注“预置演示数据 / 非实时”，不含实时模型结果。

交互演示：先按《部署与评测》安装依赖，再双击根目录 `离线演示.cmd`，访问屏幕显示的本地地址。离线模式强制禁用模型，使用 `demo-data/`，不会混入平时 `data/` 的历史。启动器会保留数据，不会每次清空。

普通使用：先停止同端口离线演示，再双击 `启动数策.cmd`。普通模式用 `data/`；没有模型配置时仍能做确定性计算。停止默认端口用 `停止数策.cmd`。切换模式时若端口被占用，先关闭原实例，或按部署手册指定另一端口；不要结束所有 Python 进程。

## 用模拟业务走完一次

1. 打开首页“两店完整演示”。这些记录明确为模拟数据，不是商家实绩。
2. 阅读任务口径：2026-09-21 至 09-27 为本期；净交易额包含负向交易。对照数为本期 2866 元、目标 2660 元，8 组门店/商品中 7 组达标。不要将净交易额叫作利润。
3. 选择南门拿铁：本期 312 元、目标 500 元，缺口 188 元。展开证据，检查交易明细、目标和日运营记录。证据分页只影响显示；下载 CSV 取得该证据的全部明细。
4. 日运营缺少一天以及不可售 180 分钟是调查线索，不能据此计算损失，更不能认定因果。先核对原表与门店说明。
5. 分别填写已验证事实、待验证解释、下一步核查。生成报告后在历史里重开，确认保存的是所选期间和当时的判断。
6. 导出 HTML/打印、Excel 和 JSON，回查相应证据 CSV。Excel 修改不会回写系统。离线模式不会伪造 AI 摘要；报告和人工判断仍能保存。

## 换成自己的三张表

从页面下载销售、目标、日运营模板，再分别上传 CSV 或 XLSX。第一行必须是非空、唯一的列名，不要插入合并标题或多行表头。每个文件最多 100MB；销售最多 600000 行，目标、运营辅助表各最多 20000 行；XLSX 解压体积另有限制。超限应按业务期间拆分，不要强行删除核查所需的记录。

导入时逐个确认字段映射，尤其是日期、门店 ID、商品 SKU、数量和成交单价。名称相同不意味着 ID 相同；ID 错配会造成三表不齐。金额单位必须一致，不能混合币种。不要将目标总额作为每一天的目标重复填入。

预览和质量结果出现问题时，下载诊断记录，根据原始行号回源表修正后重新导入。空日期、无效数字等问题行可能被隔离；隔离不等于业务上已无效。重复记录、重叠目标、来源冲突等阻断项不能靠勾选“完整”消除。

选择本期、基期、指标和范围后，只有确实收到完整的所选销售范围，才勾选完整交接并填写确认依据。未确认时，系统只统计已提供记录，不判定目标达成。完整交接的确认来自你，系统不能自动证明遗漏不存在。

缺记录与零值不同：未确认范围的空销售不能直接视为零；无目标、零目标、未知实际分别显示不同状态。零目标不计算百分比达成率。运营缺日不会被补成正常营业。对齐前后金额控制不一致时，应停止解释，先查数据。

报告是保存后的快照；更换原表或追加本期数据需要新建复盘。复盘后续可关联前次报告，但前次必须早于本期，且基期、指标、单位满足页面校验。所有“原因”和改进措施都应由业务人员核查后决定。

## 原单表探索

`/explore` 保留订单与内容探索。先看来源、单位、有效/隔离行，再按明确日期和指标问数。模型只规划受限分析工具，数值由代码计算；无模型时使用规则规划，界面会标明。内容点击率按总点击/总曝光计算，不是简单平均。没有可靠订单 ID 时，不能把记录行数当订单数。

## 模型、保存与常见问题

普通模式点击页面右上角“模型设置”，填写 API 地址、模型 ID 和 API Key。点击“测试连接”检查服务是否能返回兼容 JSON 对话，再“保存并使用”，立即生效，无需重启。密钥不会回显，地址不变时留空可继续使用原密钥；换地址必须重新填写。默认仅当前运行使用，重启后恢复此前配置。勾选“记住到本机”会把密钥明文写入本项目 `.env`，不要共享该文件。也可继续参考 `.env.example` 手工配置后重启。密钥不要写进报告或发到聊天。离线模式无视已存在的模型配置。启动和停止不会管理外部模型网关；网关不可用时可继续结构化分析。

| 现象 | 处理方式 |
| --- | --- |
| 启动未成功或端口占用 | 看启动输出及 `work/server-端口.log`，用 service.py status 检查。路径/数据/模式不符时不会复用；换端口或从原目录停止。 |
| 输入错误 / 422 | 检查必填字段、映射、日期和范围；修正后提交。不要重复点击保存。 |
| 数据指纹不符 / 409 | 保留原目录和备份，停止使用损坏数据，核查后恢复到新目录；不要直接修改 SQLite。 |
| 数据库或文件暂不可用 / 503 | 检查剩余空间、目录权限、文件占用和重复实例；保留页面草稿，核查历史里是否已保存，再重试。 |
| 模型认证、余额错误 | 停止重试，核对账户与配置。系统不使用假 AI 替代。 |
| 模型限流、网络或格式错误 | 系统只做有限重试；失败状态中保留尝试记录。稍后再试或用离线分析。 |
| 不确定保存是否成功 | 先查看历史和重开报告，核对内容；不能仅因按钮被点过就视为成功。 |

数据默认留在本机；普通模式的 AI 功能会把构造的分析上下文发送到所配置的模型服务。不要将未经许可的公司数据导入演示电脑。备份包含原表和保存记录，应由你保管，不能公开分享。具体备份、校验、恢复与源码回退见《回退说明》。

## 5 分钟上手

首次安装耗时取决于下载速度，不计入这 5 分钟。已安装依赖后：

| 时间 | 动作 | 完成标准 |
| --- | --- | --- |
| 0–1 分钟 | 双击 `离线演示.cmd`，打开屏幕地址 | 显示离线/规则模式，服务可访问 |
| 1–2 分钟 | 点击“两店完整演示”，看口径与交接声明 | 能解释 2866 / 2660 元与 7 / 8 |
| 2–3 分钟 | 找南门拿铁，展开销售/目标/运营证据 | 看见 312 / 500 元，运营缺日不是零 |
| 3–4 分钟 | 分别写事实、假设、下一步核查，保存 | 历史中能重开报告；原快照仍在 |
| 4–5 分钟 | 导出 Excel/JSON/HTML，双击停止入口 | 文件可打开，状态检查确认已停 |

如果只看静态成果，直接双击 `outputs/offline-demo-v2.7.0/index.html`；不需要先启动服务。

准备：先安装依赖、关闭占用端口的旧实例；只用模拟数据，准备 `examples/failure-empty.csv`。这是一份可照读的脚本，不表示讲解者已完成练习。

| 时间 | 操作 | 可以说什么 | 失败时怎么演示/恢复 |

| 7:00–8:00 | 历史重开，导出 HTML/Excel/JSON | “这些是当时的快照，后来换表不会改掉旧报告。Excel 有三张工作表，修改不回写系统。” | 下载失败先查服务状态和磁盘；报告已保存时从历史重新导出 |

## 网页配置模型的具体步骤

1. 停止离线实例，双击“启动数策.cmd”进入普通模式；离线模式会明确禁用保存与连接测试。
2. 在经营复盘或单表探索页面，点击右上角“模型设置”。地址和模型 ID 必须使用服务商提供的值，仅有 Key 通常不能确定是哪家服务或哪个模型。
3. 输入 API Key（密码框）。已有密钥只显示“已配置”，不会回传；更换 API 地址时请提供该服务对应的新 Key。
4. 选择是否“记住到本机”。不勾选仅当前服务进程生效；不会删除此前已保存的本机配置。勾选会明文保存到本项目 .env，保留其他设置；不要公开分享 .env。
5. 点击“测试连接”。会发送一条不含业务数据的极小请求，可能产生少量服务商费用；测试成功不等于保存，也不证明所有业务问题都能答对。
6. 点击“保存并使用”，状态立即更新，输入框清空；此后可在现有流程生成受约束 AI 摘要。关闭设置弹窗也会清空未保存的密码输入。
7. 不再使用时点击“清除配置”，确认后关闭本工作台的模型配置（包括已记住的 Key）。不会修改外部网关或其他软件；工作数据与报告保留。

故障：401 核对 Key；402 核对账户额度；429 等待限流恢复；404 核对服务地址/模型 ID；超时或不兼容 JSON 检查服务商能力。失败不会覆盖已有配置。两个窗口同时修改时，后一个会提示重新打开，避免覆盖新设置。明文配置只适合本人电脑上的本地工作台，不提供共享服务器的多用户密钥管理。
